# Location And Battery Policy

## 최우선 원칙

위치 공유 기능은 배터리 최적화를 최우선으로 설계합니다.

MVP에서는 사용자의 장기 위치 기록을 만들지 않고, 방문 세션 중 동의한 사용자끼리 최신 위치를 공유하는 데 집중합니다.

쉽게 말해, MVP 서버는 “오늘 사용자가 어디를 돌아다녔는지”를 저장하지 않습니다. “현재 마지막으로 확인된 위치가 어디인지”만 저장하고 새 위치가 오면 이전 값을 덮어씁니다.

## 권한 요청 시점

- 앱 설치 직후 위치 권한을 요청하지 않는다.
- 장소 목록, 할인, 체크리스트, 시설 지도 조회에는 위치 권한이 필요하지 않다.
- 사용자가 방문 세션을 시작한 뒤 위치 공유를 켤 때 권한을 요청한다.
- 권한을 거부해도 시설 지도는 제한적으로 사용할 수 있어야 한다.

## 위치 공유 기본값

```text
default: off
```

위치 공유는 항상 사용자가 직접 켜야 합니다.

## 위치 공유 상태

```text
off
requesting_permission
sharing
battery_saver
permission_denied
stopped
```

방문 종료가 발생하면 어떤 화면에 있든 `stopped`로 전환하고 위치 전송을 중단합니다.

## 갱신 주기 정책

| 상황 | 권장 동작 |
| --- | --- |
| 방문 전 | 위치 공유 없음 |
| 방문 시작 전 | 권한 요청 없음 |
| 방문 시작 후 사용자가 동의 | 위치 공유 시작 |
| 지도 화면 활성 | 10~30초 간격 갱신 |
| 지도 화면 비활성 | 더 긴 간격 또는 마지막 위치만 유지 |
| 일행 찾기 모드 | 제한된 시간 동안만 빠른 갱신 |
| 장시간 정지 상태 | 갱신 중단 또는 간격 증가 |
| 배터리 20% 이하 | 절전 모드 전환 |
| 방문 종료 | 위치 전송 중단 및 위치 만료 |

5초 이하의 고정 주기 위치 전송은 기본값으로 사용하지 않습니다.

## Native 확장 전략

MVP는 Flutter로 시작합니다. 다만 위치 엔진은 `core/location_engine` 뒤에 숨겨서 나중에 Native 최적화를 붙일 수 있게 합니다.

가능한 확장 방식:

1. Flutter 위치 패키지로 MVP 구현
2. 배터리 또는 백그라운드 제어 문제가 확인되면 Android/iOS Native code 추가
3. 필요하면 `packages/native_location_bridge` 형태의 Flutter plugin으로 분리

전체 앱을 Native로 재작성하지 않고, 위치 수집 엔진만 교체 가능하게 유지합니다.

## 서버 저장 정책

- 서버에는 최신 위치 스냅샷 중심으로 저장한다.
- 위치 히스토리를 무제한 저장하지 않는다.
- `expiresAt`을 필수로 둔다.
- 방문 종료 후 위치 스냅샷은 즉시 삭제하거나 짧은 만료 시간을 적용한다.
- MVP에서는 이동 경로 분석, 체류시간 분석, 장기 위치 기록 저장을 하지 않는다.

## 통신 방식

MVP에서는 구현 단순성과 배터리 효율을 우선해 REST 기반 업데이트/조회로 시작합니다.

- 위치 업로드: 사용자가 위치 공유를 켠 동안 제한된 간격으로 최신 위치를 서버에 보낸다.
- 위치 조회: 일행방 화면 또는 지도 화면에서 10~30초 이상 간격으로 마지막 위치를 조회한다.
- WebSocket 또는 실시간 스트리밍은 MVP 이후 실제 필요성이 확인되면 검토한다.
